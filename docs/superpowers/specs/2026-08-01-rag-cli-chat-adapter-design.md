# Modelable CLI RAG Chat Adapter Design

## Goal

Make documentation RAG available from the existing `modelable llm chat` CLI while preserving the current conversational commands and the shared RAG retrieval/generation core.

## Scope

This slice adds an opt-in documentation index to the CLI chat command. When configured, users can run `/docs <question>` in an interactive chat or pass the same command through `--message`. The adapter delegates retrieval, deterministic context selection, evidence prompting, citation formatting, and insufficient-evidence behavior to the existing `modelable.rag` implementation.

The LSP and web playground are deliberately out of scope for this slice. They will consume the same RAG service boundary in later adapters rather than receiving CLI-specific behavior.

## User interface

`modelable llm chat` gains:

```text
--docs-index PATH
```

The option points to the single binary Searchable index manifest accepted by `DocumentationRetriever`. Without the option, existing chat behavior is unchanged. With the option, the interactive help includes:

```text
/docs <question>  Answer using the configured documentation index.
```

Invoking `/docs` without `--docs-index` returns a clear configuration error and does not send the command to the general LLM conversation. An empty `/docs` question returns the existing command-usage response.

## Architecture and data flow

The CLI command constructs one `DocumentationRetriever` when `--docs-index` is supplied and passes it to the chat command adapter. The adapter recognizes only messages whose trimmed text begins with `/docs`; all other messages continue through `ConversationSession.turn` unchanged.

For a documentation question:

1. Parse the command and validate that a question is present.
2. Require the configured retriever and the existing provider.
3. Call `answer_with_retrieval(retriever, provider, question)`.
4. Return the answer text, including the shared `[S1]` citation references and `Sources:` section.

The adapter must not duplicate prompt construction, ranking, context budgeting, citation labels, or evidence thresholds. The retriever is created once per CLI invocation so index loading and client setup are not repeated for each question.

## Error handling

- Missing `--docs-index`: report that `/docs` requires the option and leave the session usable.
- Missing LLM provider: report the existing provider configuration error through the normal CLI path.
- Invalid or unreadable index: fail during command setup with the retriever's existing validation error.
- No retrieved evidence: preserve `answer_with_retrieval`'s insufficient-evidence response.
- Provider failure: preserve the existing provider exception/error rendering path used by the chat command.

## Testing

Add focused CLI/chat tests covering:

- `/docs` uses the configured retriever and shared answer function.
- `/docs` without an index reports configuration guidance.
- ordinary chat messages still use `ConversationSession` when an index is configured.
- single-message and interactive paths expose the same command behavior.
- citations and insufficient-evidence output remain those generated by the shared RAG core.

Update CLI help/documentation to describe the opt-in index and command. Existing chat, RAG generation, and provider tests must continue to pass.

## Compatibility and non-goals

- No new runtime dependency is introduced.
- No embedding provider is bundled; the index remains compatible with the existing injected/provider configuration.
- No changes are made to `ConversationSession`, LSP conversation protocol, or web worker protocol in this slice.
- No index copying, conversion, or per-document files are introduced; the configured path remains the one binary Searchable index manifest.
