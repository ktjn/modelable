## Feedback and remaining work

- `--check-report` requires every `<testcase>` in a supplied JUnit XML file to bind exactly one requirement via a `verifies` property and matches `Evidence.provenance` against individual testcase IDs (`classname::name` or `test` property). Brownfield characterization runs that execute broader multi-test suites or file-level provenance (such as `ev-mod-comp-10-recovery-linux`) should continue using `Evidence.artifacts` hash bindings unless a dedicated single-requirement JUnit report is emitted.
- External Python consumers, remaining operational fault families, cleanup/crash ownership, manual/model UI acceptance, shared IR/classification/formal/quality criteria and release decisions remain open.
