# Plan: Fix Missing `uuid` Dependency in Cargo.toml for Semantic Types with `uuid(N)`

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** When a `semantic` type is declared with `uuid(N)` (e.g. `semantic AccountId: uuid(7)`), the generated Rust code must emit `// requires: uuid (https://docs.rs/uuid)` so that the multi-package `Cargo.toml` emitter (PR #316) includes the `uuid` dependency. Currently the dependency is missing because `_emit_semantic_type()` builds its header manually without calling `_header_lines()`.

**Spec:** Issue [#327](https://github.com/ktjn/modelable/issues/327) — the issue body serves as the design specification.

**Root cause:** `_emit_semantic_type()` at `cli/src/modelable/emitters/rust.py:586` builds the comment header with a bare `["// @generated by Modelable"]` instead of calling `_header_lines()`. Both `_emit_model()` and `_emit_projection()` call `_header_lines()` with dependency flags derived from field specs, so they correctly emit `// requires: uuid` when `uuid::Uuid` appears in any field annotation. But `_emit_semantic_type()` never does, so even though the generated struct body `pub struct BuyerId(pub uuid::Uuid)` references `uuid::Uuid`, the `// requires:` comment is absent. Since `_emit_cargo_toml()` (line 290) scans artifacts for the literal string `"requires: uuid"` to decide whether to include `uuid` in `[dependencies]`, the dependency is silently omitted.

## Global Constraints

- Single-crate output path must be unaffected — it doesn't generate `Cargo.toml` at all, so `// requires:` comments are informational only. The fix is still correct for single-crate mode, but a regression in model/output content would break existing tests.
- The fix should handle not just `uuid` but all primitive types that map to optional-dependency Rust types: `serde_json::Value` (from `json`), and any future additions. Check which primitive types in `_primitive_to_rust()` map to types requiring external crates.
- Every changed file must pass `uv run ruff format --check .`, `uv run ruff check .`, and the mypy baseline ratchet before its commit.
- Branch: work happens on a feature branch from `main`.

**Interfaces:**

- `_any_needs_*` helpers are not directly usable here because they operate on `_FieldSpec` lists, which don't exist for semantic type declarations. Instead, the fix inspects `rust_type` directly.

- [ ] **Step 1: Understand the mapping**

  `_primitive_to_rust()` maps these primitives to external-crate types:
  - `"uuid"` → `"uuid::Uuid"` (requires `uuid` crate)
  - `"json"` → `"serde_json::Value"` (requires `serde_json` crate)

  `_emit_cargo_toml()` checks for `"requires: uuid"` and `"requires: serde_json"`. So `_emit_semantic_type()` must emit these when the underlying type is `uuid` or `json`.

  Additionally, `DecimalType` maps to `String` (no external dep), and `FixedBinaryType` maps to `[u8; N]` (no external dep). NamedType underlying types produce `use` statements but no new crate requirements beyond what the referenced type's own artifact declares. So we only need to handle `uuid` and `json`/`serde_json` from the primitive path.

- [ ] **Step 3: Write the implementation**

  In `_emit_semantic_type()` (line 565), after `rust_type` is determined (line 577) and before the header is built (line 586):

  Replace:
  ```python
  lines = ["// @generated by Modelable"]
  ```

  With:
  ```python
  needs_uuid = rust_type == "uuid::Uuid"
  needs_serde_json = rust_type == "serde_json::Value"
  lines = _header_lines(uuid=needs_uuid, serde_json=needs_serde_json)
  ```

  This reuses the existing `_header_lines()` function, ensuring the `// requires:` string format is identical to what `_emit_model()` and `_emit_projection()` produce, so `_emit_cargo_toml()`'s string scan picks it up correctly.

  The `use_statement` (from `_rust_type_for_semantic_underlying` returning it for NamedType underlying types) must still be inserted after the header. Keep the existing logic at line 587-588 that appends `use_statement` if present.

## Self-Review Notes

- **Minimal change surface:** The fix is a single-line replacement in `_emit_semantic_type()` — replacing the manual header with a call to `_header_lines(uuid=..., serde_json=...)`. No changes to `_emit_cargo_toml()`, the package emitter, or the single-crate emitter.
- **Correctness for NamedType underlying:** When the underlying type is a `NamedType`, `rust_type` is the type name (e.g. `"SomeOtherType"`) and `use_statement` is set. Our flag check (`rust_type == "uuid::Uuid"`) correctly evaluates to False, so no spurious `// requires:` comment is emitted. The `use_statement` is still appended after the header by the existing code.
- **Single-crate mode:** The `// requires:` comments are informational in single-crate mode (no Cargo.toml is generated). Adding them is harmless and actually makes the generated code more self-documenting.
- **Other dependency types:** If future primitive types map to external crates (e.g. `chrono`), the same pattern should be followed — check `rust_type` against the expected Rust path and pass the corresponding flag to `_header_lines()`.
